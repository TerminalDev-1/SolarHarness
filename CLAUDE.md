# CLAUDE.md

This branch (`desktop`) holds only the Solar desktop app (Electron). The engine is the Solar Harness CLI on `main`, installed as the `solar-harness` dependency from GitHub (`github:TerminalDev-1/SolarHarness#main`); its `prepare` script builds `dist/` on install. `.npmrc` sets `allow-git=root` and `package.json` `allowScripts` approves that build, both required by npm 12. Engine changes (harness, Codex provider, tools) go on `main`, then `npm update solar-harness` here picks them up. Never copy engine code into this branch.

`npm start` launches the app. `main.js` drives `SolarHarness` from `solar-harness/dist/*` over IPC (`preload.cjs` exposes `window.solar`). The renderer is dependency-free ES modules in `renderer/` with a strict CSP; model text is rendered through DOM APIs, never innerHTML. Diffs: `changes.js` snapshots the workspace's text files before each turn and turns each `File: Created/Edited/Deleted x` event into red/green hunks (jsdiff), plus a session-wide Review list. `browser-control.js`: between turns the app hides the engine's "controlling the browser" notice, tint, and cursor (also on pages loaded meanwhile) and shows them again when a turn starts; it reads SolarBrowser's private `context`, so recheck it when the engine's browser changes. CLI parity: every CLI slash command works from the composer's `/` menu (`SLASH_COMMANDS`/`COMMANDS` in `app.js`); their output is a local `note` card, never presented as a Solar reply. Mode tabs are Chat, Plan, Ultra (hover cards from `MODE_INFO`); Ultraplan and Ultrareview are `/ultraplan` and `/ultrareview` only. Ultra locks the effort and speed pills at Max and Fast (`.locked` with `aria-disabled`, not `disabled`, so `PILL_TIPS` cards still explain the pin); an `/ultraplan` or `/ultrareview` turn speeds up the rainbow while it runs. Solar can switch modes itself (engine `switch_mode` tool): its `Mode: X` activity becomes a "Switched to X" timeline step, and a plan it drafts comes back as `result.plan`, which `main.js` returns as a normal plan card for approval. Delegation: a reply with `readyToDelegate` (the user asked for a team in any wording, via the engine's `switch_mode` delegate, or `/delegate`, which uses the last request and before any request only shows a hint note) carries a sub-agent plan shown as a review card; `chat:runDelegation` runs the accepted agents and streams `solar:agents` to a live team panel. Auto-approve skips the card. Side-by-side (v1.4 Reborn): `/sidebyside <request>` (a request to act on: Aurora does it and edits, Helios inspects and verifies read-only; Aurora's `File:` events become diffs) calls `chat:meeting` (`harness.sideBySide`), whose per-session status and messages stream as `solar:meeting`; two panes (Aurora, Helios) replace the thread, each with its own status, session ID, activity, and scrolling history. Follow-ups resume both sessions, Tab selects a pane and PgUp/PgDn scroll it, images wait, and `/sidebyside close`, Leave, or any other command (never mid-round) returns to chat with a note linking the engine's `.solarharness/sessions` recordings. While a round runs, each pane lists the steps its session reports; they give way to the reply when it arrives. Themes: dark (default) and light, set by the sidebar sun/moon button or `/theme`, saved in preferences; `:root[data-theme="light"]` overrides the palette plus the hard-coded dark colors, text in sun colors uses `--sun-text`/`--sun-link`, and `main.js` recolors the title bar overlay. Pets are the engine's ASCII sprites (`pets:frames`) walking along the composer. `npm run demo` runs a scripted harness that edits a temp folder (a message containing "stress" writes 60 large files); `npm run screenshots` renders offscreen (no window appears), saves views to `screenshots/` (not committed), and prints `early delegate: ... OK` only if `/delegate` in a fresh chat shows a hint rather than a failed turn, `stress layout: ... OK` only if the composer stays inside the window, `narrow composer: ... OK` only if the composer controls fit with the Review panel open, `cli parity: ... OK` only if the / menu, notes, pet, three tabs, pins, a scripted self-chosen plan ("plan it first"), and a scripted delegation (card, accept/reject, team panel) all work, `themes: ... OK` only if the toggle and `/theme dark` switch themes (views saved as `light-*.png`), `side by side: ... OK` only if a scripted meeting fills both panes, a follow-up resumes the same sessions, Tab switches panes, the composer stays on screen, and `/sidebyside close` returns to chat with its note, and `ultra pins: ... OK` only if Ultra shows and locks Max effort with Fast speed (Speed is a Fast/Standard picker; Ultra overrides it only for display, the engine applies it per turn). Check UI changes with it; it proves layout, not live Codex behavior.

Rules:
- Update this file for architecture or contract changes. After verifying a requested change, commit only its files and push.
- UI: dark theme (plus a light theme; keep both readable) with sun accents, the spinning full-spectrum rainbow composer frame (faster while working, fastest in Ultra), green/red diffs with word-level highlights. Keep the Review panel and the timeline truthful: show only activity the harness actually reported.
- A new chat in a folder named `test` empties it, so always confirm first.
- Layout: `.app` is one grid row the height of the window and every column has `min-height: 0`; lists scroll inside their panel. Never let a panel grow the page, or the composer falls off screen.
