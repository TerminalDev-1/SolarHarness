# CLAUDE.md

This branch (`desktop`) holds only the Solar desktop app (Electron). The engine is the Solar Harness CLI on `main`, installed as the `solar-harness` dependency from GitHub (`github:TerminalDev-1/SolarHarness#main`); its `prepare` script builds `dist/` on install. `.npmrc` sets `allow-git=root` and `package.json` `allowScripts` approves that build, both required by npm 12. Engine changes (harness, Codex provider, tools) go on `main`, then `npm update solar-harness` here picks them up. Never copy engine code into this branch.

`npm start` launches the app. `main.js` drives `SolarHarness` from `solar-harness/dist/*` over IPC (`preload.cjs` exposes `window.solar`). The renderer is dependency-free ES modules in `renderer/` with a strict CSP; model text is rendered through DOM APIs, never innerHTML. Diffs: `changes.js` snapshots the workspace's text files before each turn and turns each `File: Created/Edited/Deleted x` event into red/green hunks (jsdiff), plus a session-wide Review list. `browser-control.js`: between turns the app hides the engine's "controlling the browser" notice, tint, and cursor (also on pages loaded meanwhile) and shows them again when a turn starts; it reads SolarBrowser's private `context`, so recheck it when the engine's browser changes. CLI parity: every CLI slash command except `/theme` (the app is dark-only) works from the composer's `/` menu (`SLASH_COMMANDS`/`COMMANDS` in `app.js`); their output is a local `note` card, never presented as a Solar reply. Modes are Chat, Plan, Ultra, Ultraplan, Ultrareview (tabs with hover cards from `MODE_INFO` saying what each does, whether it can edit files, and its effort and speed; or one mode pill when the composer is narrower than 760px); the Ultra modes show and lock Max effort, and Ultra also Fast (pills are `.locked` with `aria-disabled`, not `disabled`, so their hover cards from `PILL_TIPS` still explain the pin). Delegation: a reply with `readyToDelegate` (or `/delegate`, which uses the last request) carries a sub-agent plan shown as a review card; `chat:runDelegation` runs the accepted agents and streams `solar:agents` to a live team panel. Auto-approve skips the card. Pets are the engine's ASCII sprites (`pets:frames`) walking along the composer. `npm run demo` runs a scripted harness that edits a temp folder (a message containing "stress" writes 60 large files); `npm run screenshots` renders offscreen (no window appears), saves views to `screenshots/` (not committed), and prints `stress layout: ... OK` only if the composer stays inside the window, `narrow composer: ... OK` only if the composer controls fit with the Review panel open, `cli parity: ... OK` only if the / menu, notes, pet, ultra pins, and a scripted delegation (card, accept/reject, team panel) all work, and `ultra pins: ... OK` only if Ultra shows and locks Max effort with Fast speed (Speed is a Fast/Standard picker; Ultra overrides it only for display, the engine applies it per turn). Check UI changes with it; it proves layout, not live Codex behavior.

Rules:
- Update this file for architecture or contract changes. After verifying a requested change, commit only its files and push.
- UI: dark theme with sun accents, the spinning full-spectrum rainbow composer frame (faster while working, fastest in Ultra), green/red diffs with word-level highlights. Keep the Review panel and the timeline truthful: show only activity the harness actually reported.
- A new chat in a folder named `test` empties it, so always confirm first.
- Layout: `.app` is one grid row the height of the window and every column has `min-height: 0`; lists scroll inside their panel. Never let a panel grow the page, or the composer falls off screen.
